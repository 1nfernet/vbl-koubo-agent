# VBL Script Craft (口播文案与提词重塑技能)

面向严肃技术中视频（3~5分钟）与高信息密度口播的工程化规范。
核心准则：**尊重原作者事实与叙事骨架，专注口语去打结、气口断句与提词交付，严禁盲目删减总结与栏目仪式。**

---

## 一、 核心写作与重塑铁律 (Core Craft Principles)

1. **修补打结，不推翻重构**：
   - 严禁擅自抹杀作者原有的开场（如“欢迎收看本周开源软件汇总”）和片尾互动（如“相关资料放粉丝群”）。
   - 只对长难句、逻辑断层、口语打结处做手术（例如将“然后在然后通过再交给”改为“最后交给”）。
2. **长短呼吸律 (Pacing & Breath)**：
   - 单句字数控制在 14~18 字以内。
   - 复杂长句必须用自然逗号、句号拆解为两个分句，为录制留出呼吸气口。
3. **技术名词与文化锚点保真**：
   - 专有名词绝不缩写抹去（例如保留 `Agent-Reach`、`HyperFrames`、`Impeccable`、`OpenCut`、`FFmpeg`）。
   - 保留作者点出的生动概念（如“Vibecoding”、“9万星替代品”）。
4. **数字发音确定性**：
   - 版本号、百分比口播转汉字读音（如 `5.5` -> `五点五`，`72.6%` -> `百分之七十二点六`，`9万` -> `九万`）。

## 二、 两类场景模式路由 (Mode Routing)

根据输入素材的长度与体裁自动或显式匹配模式：

### 模式 A：`deep_explainer`（3~5分钟 深度/汇总中视频，默认模式）
- **适用**：多工具盘点、深度原理拆解、教程分享。
- **结构约束**：
  1. **栏目开场 (0-15s)**：交代背景、本期看点、承接互动。
  2. **核心主体 (15s-3min)**：按工具/论点分段展开，每段保持“是什么 -> 为什么火 -> 核心工作流”。
  3. **体系串联总结 (3min-4min)**：必须将提到的多个工具重新串成完整的工作流闭环（不可删减！）。
  4. **行动指引与号召 (4min-5min)**：资源群引导、下期预告、固定结语。

### 模式 B：`short_punch`（60~90秒 短视频极速流）
- **适用**：单点新闻曝光、单工具测评、痛点打脸。
- **结构约束**：
  1. **黄金 3 秒**：直接抛反常识事实或最炸裂效果。
  2. **核心证据**：直给数字与对比。
  3. **收尾**：留给观众判断或单点行动。

## 三、 提词器排版与交付契约 (Delivery Format)

重塑完成后的文案，必须输出为**带机位/气口与预估秒数**的提词格式：

```text
/* RUN MANIFEST */
/* Style: VBL Deep Explainer | Target WPM: 250 */

【🔥 栏目开场】 (预估秒数)
  句子一。
  句子二。

【📌 模块一：xxx】 (预估秒数)
  句子三。
  **核心重音或数据加粗**。
```

## 四、 黄金对照案例 (Calibration Case)

### 输入草稿：
> 第一个是 HyperFrames，这是一个超级火爆的项目，这是 HeyGen 开源的一个视频项目。这个项目的解决方案是是用写网页的方式来做视频。它和普通剪辑软件不一样的地方在于 Ai可以调用它来直接用HTML用代码写视频...最后再交给 FFmpeg 渲染成 MP4...

### 重塑成稿（达标标准）：
> 第一个是 HyperFrames。
> 这是 HeyGen 开源的一个视频项目，在社区非常火爆。
> 它的核心逻辑，是用**写网页的方式来做视频**。
> 与普通剪辑软件不同，Agent 可以直接调用它，用 HTML 代码写视频。
> 最近爆火的 Vibecoding 动画，基本都是这么写出来的。
> 最后交给 FFmpeg，秒级渲染成 MP4、MOV 等格式。
